# План итоговой доработки ИДЗ1

## Исходное состояние

Проверена временная копия текущих исходников на 127.0.0.1:5173. Прямой запуск из папки проекта упёрся в ограничения записи кэша Vite. В копии прошли сборка, mock-регистрация, минутная сессия с паузой и продолжением, переход между экранами и появление одной записи после обновления страницы. Остров достиг 14 из 14 построек. Звук завершения и полный перезапуск сервера отдельно не проверялись.

PRD стоит уточнить в части уведомления: на таймере виден баннер, всплывающее уведомление появляется при завершении на другом экране. Для дизайна используем `ref-02.jpg` для композиции острова, `ref-04.jpg` для иерархии веб-таймера и `ref-07.jpg` для дома и тёплого света. После завершения добавлена ссылка «Посмотреть в журнале».

## Переход на Supabase

1. Сохранить локальный запуск React/Vite. Подключить существующие формы к Supabase Auth. Реализовать регистрацию по email и паролю с реальным письмом, экран ожидания подтверждения и обработку ошибки ссылки. Проверить доставку и вход после подтверждения. Для доставки на адреса вне команды проекта настроить SMTP. Подключить Google OAuth с разрешённым локальным адресом возврата. Проверить первый и повторный вход, выход и восстановление сессии. В `.env.example` оставить пустые Project URL и publishable key. Секреты провайдеров хранятся в настройках сервиса.
2. Добавить SQL-миграцию для пользовательского состояния и журнала Pomodoro. Связать строки через `user_id` с аккаунтом Supabase и включить RLS. Настройки, остров, биом, атлас и статистика сохраняются в базе. Завершение сессии и изменение прогресса выполняются атомарно. Стабильный ID предотвращает дубли при повторном сохранении. При ошибке показать статус и дать повторить.
3. Сохранить старые данные localStorage. Итоговый прогон выполнить с новым тестовым аккаунтом. Если потребуется перенос истории, отдельно согласовать явный импорт прогресса без локальных учётных данных.
4. Пройти основной сценарий. Сначала устранить подтверждённые проблемы понятности, затем сверить оформление с выбранными референсами. Обновить PRD, DESIGN и ARCHITECTURE по фактическим изменениям, README по запуску и настройкам.
5. Проверить письмо, оба входа, минутную сессию и сохранение после обновления страницы и перезапуска Vite. Проверить доступ к своим данным во втором браузере и изоляцию второго аккаунта. Зафиксировать результаты в `submission/CHECKLIST.md`.
6. Собрать ZIP с миграцией, `.env.example`, инструкцией запуска, документацией, референсом и рефлексией на 5–10 строк. Исключить зависимости, сборку, кэш, реальные настройки и секреты. Проверить запуск распакованной копии. Подготовить комментарий по фактическому прогону и видео локального запуска до минуты.

## Статус Supabase Auth

Клиентская интеграция добавлена. Живые проверки требуют доступа к проекту Supabase, настройкам Google Cloud и тестовому ящику. Проект pomodoro_timer_game подключён через `.env.local`. В Supabase подтверждение email включено, Site URL и оба локальных адреса возврата сохранены. Локальный экран открывается в режиме Supabase. Штатная ссылка подтверждения поддерживается через PKCE. Для произвольных адресов нужен Custom SMTP.

| Сценарий | Результат |
|---|---|
| Письмо получено → адрес подтверждён → вход работает | Реальное письмо получено во входящих. После перехода по ссылке экран показал «Ссылка недействительна», однако последующий вход с паролем открыл экран таймера при включённом обязательном подтверждении адреса. Обработчик исправлен: проверенное подтверждение без сессии предлагает вход с паролем, сбой обмена кода отделён от недействительной ссылки. Эти ветки и восстановление сессии прошли на локальном стенде. Позднее Gmail SMTP доставил подтверждение на учебный адрес. Supabase зафиксировал подтверждение. В последнем прогоне старая использованная ссылка и произвольный неверный токен отклонены с предложением повторной отправки. |
| Google-аккаунт выбран → приложение открылось под этим аккаунтом | Проект Google Cloud «Pomodoro Island» и веб-клиент созданы. Google включён в Supabase. В реальном браузере проверены выбор аккаунта, отмена, успешный возврат с Google, открытие таймера под Google-аккаунтом, восстановление сессии после обновления, выход и повторный вход. |

### Gmail SMTP

Custom SMTP включён через Gmail (`smtp.gmail.com:587`), отправитель — Pomodoro Island. Первоначальный тест вернул `535 5.7.8`. После замены пароля приложения повторная регистрация была принята Supabase. Тестовое письмо на учебный адрес подтверждено в папке «Отправленные» Gmail 22 ноября 2026 в 17:56 МСК. Получение подтверждено пользователем. В Supabase учебный аккаунт отмечен подтверждённым в 17:57 МСК.

Для подтверждённых аккаунтов добавлено восстановление пароля из формы входа. Сборка и пять сценариев обработчика ссылки проверены. Живой прогон письма восстановления и смены пароля ещё не выполнен.
