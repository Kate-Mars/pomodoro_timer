# Pomodoro Island («Остров»)

Помодоро-таймер, во время которого на парящем воксельном острове вырастает маленький уютный мир. Учебный проект ИДЗ1.

Документы: [PRD.md]](PRD.md) (требования и статус), [DESIGN.md]](DESIGN.md) (дизайн-система), [REFLECTION.md]](REFLECTION.md).

## Требования к среде

- **Node.js 22.12+** и npm. SDK Supabase требует Node 22+, Vite 7 на ветке 22 требует 22.12+.
- Современный браузер: Chrome, Edge, Firefox или Safari последних версий.
- Открывать приложение нужно по `localhost`: Web Crypto (хеширование паролей) работает только в безопасном контексте.

## Установка и запуск

```bash
cd /путь/к/распакованному/проекту
npm ci
npm run dev
```

Откройте **http://localhost:5173** (порт закреплён в `vite.config.ts`; если он занят, Vite сообщит об ошибке).

Другие команды:

```bash
npm run build     # проверка типов (tsc) и production-сборка в dist/
npm run preview   # просмотр собранной версии: http://localhost:4173
```

Примечание: в `.npmrc` кэш npm перенесён в папку проекта (`.npm-cache`), чтобы обойти ошибки прав доступа к `~/.npm`. Папка в `.gitignore` и в архив не входит.

## Основные функции

1. **Таймер:** пресеты 15/25/50 и своё значение (1–180 мин), пауза и продолжение без потери времени, сброс с подтверждением. Пока сессия идёт, длительность изменить нельзя.
2. **Остров строится от таймера:** 14 построек, анимация появления, персонаж строит, радуется или отдыхает.
3. **Мир:** восемь мест (луг, пустыня, снежные горы, сакуровая роща, хвойный и осенний лес, тропический остров, грибной лес) со своей флорой, палитрой, водой, частицами и погодой; время суток (авто или вручную), погода (ясно, дождь, снег).
4. **Прогрессия мест:** три места открыты сразу, остальные открываются за 1, 3, 5, 8 и 12 завершённых сессий. Каждое место развивается от сессий, проведённых в нём. Атлас — на «Прогрессе», переключатель — в панели таймера.
5. **Звук (Web Audio, без файлов):** генеративная музыка места (аккорды, мелодии, паузы, свой лад и тембр, плавные переходы, без гула), звуки мира со своей громкостью, сигнал завершения. Mute не трогает уровень громкости.
6. **Прогресс:** статистика, график за 7 дней и журнал. Только реальные сессии.
7. **Аккаунты:** Supabase Auth с подтверждением email, входом по паролю и через Google. Без настройки Supabase доступен локальный mock-вход.
8. **Настройки:** «Таймер», «Мир», «Звук», «Внешний вид» (уровень анимации), «Данные».

Интерфейс собран на **shadcn/ui** (Radix) и Tailwind CSS 4. Компоненты лежат в `src/components/ui/`. Они добавлены вручную по исходникам стиля new-york, потому что CLI shadcn не смог скачать реестр. Игровая сцена — собственный SVG voxel-движок (`src/lib/voxel.ts`, `src/lib/world.ts`, `src/components/world/`).

## Хранение данных в локальном режиме

В этом режиме всё хранится в **localStorage этого браузера**. Сервера нет.

| Ключ | Что хранит |
|---|---|
| `pomodoro.users.v1` | Аккаунты: имя, email, соль и хеш пароля |
| `pomodoro.auth.v1` | Кто сейчас вошёл |
| `pomodoro.v1@<id>` | Длительность, mute, прогресс острова |
| `pomodoro.biome.v1@<id>` | Текущее место |
| `pomodoro.atlas.v1@<id>` | Сессии по местам и уже показанные открытия (при первом запуске собирается из журнала) |
| `pomodoro.audio.v1@<id>` | Громкость музыки |
| `pomodoro.world.v1@<id>` | Время суток, погода, эффекты, анимации, звуки мира, сигнал |
| `pomodoro.sessions.v1@<id>` | Статистика и последние 20 сессий |

Данные переживают перезагрузку страницы и перезапуск браузера. Их удаляет очистка данных сайта. Между браузерами и устройствами они не переносятся. Данные старой версии без аккаунтов один раз переходят к первому вошедшему аккаунту.

## Ограничения mock-авторизации

- Это **учебный прототип**, а не защита. Аккаунты лежат в localStorage, и любой с доступом к браузеру может их удалить или подменить.
- Пароль не хранится в открытом виде: используется PBKDF2-SHA-256 (120 000 итераций) со случайной солью.
- Восстановления пароля, подтверждения email и входа с другого устройства нет.
- Защита от перебора (5 ошибок подряд, затем пауза 30 секунд) живёт только в памяти вкладки.
- Задержка 650 мс при входе имитирует сеть.

## Supabase Auth

1. Скопируйте `.env.example` в `.env.local`, укажите Project URL и publishable key и перезапустите Vite. Без этих параметров доступен прежний локальный режим.
2. В Supabase Auth включите провайдер Email и **Confirm email**. В URL Configuration укажите Site URL `http://localhost:5173`. В Redirect URLs разрешите `http://localhost:5173/auth/confirm` и `http://localhost:5173/auth/callback`. Если открываете Vite на другом хосте или порту, используйте этот origin во всех настройках и запускайте регистрацию и вход с него.
3. Для встроенной отправки оставьте стандартный шаблон и откройте письмо в том же браузере и профиле, где начали регистрацию: приложение обменивает код подтверждения через PKCE. Если штатная ссылка вернула маркер подтверждения без подходящей сессии, приложение проверит результат и предложит вход с паролем. Если настроен Custom SMTP, в шаблоне **Confirm signup** можно установить адрес ссылки `{{ .RedirectTo }}?token_hash={{ .TokenHash }}`. Например:

   ```html
   <p><a href="{{ .RedirectTo }}?token_hash={{ .TokenHash }}">Подтвердить адрес</a></p>
   ```

   Для изменённого шаблона приложение проверяет одноразовый токен на `/auth/confirm` и убирает параметры ссылки из адреса. Для адреса вне команды проекта настройте Custom SMTP в Supabase.
4. В Google Cloud создайте веб-клиент OAuth. В разрешённые источники добавьте origin приложения, а в Authorized redirect URIs — URL callback, показанный в Supabase в настройках провайдера Google. При тестовом статусе добавьте аккаунт в Test users. Включите Google в Supabase и сохраните Client ID и Client Secret там. Приложение принимает код на `/auth/callback` и обменивает его через PKCE. Для локального теста открывайте приложение в том же профиле браузера, из которого начали Google-вход.
5. Проверьте регистрацию через форму на доступный тестовый ящик и вход после перехода по ссылке. Для Google отдельно проверьте новый и повторный вход, отмену, выход и обновление страницы.

SMTP-реквизиты и Google Client Secret хранятся в настройках сервисов. Для нового проекта Supabase примените SQL из `supabase/migrations/20261122190000_pomodoro_progress.sql` в Supabase SQL Editor и обновите страницу. В облачном проекте Pomodoro Island миграция уже применена. После входа журнал и прогресс загружаются из PostgreSQL. Прежний локальный режим используется без настроек Supabase.

Для ранее подтверждённого адреса используйте **Вход → Забыли пароль?**. Откройте письмо восстановления в том же браузере, где запросили его, и задайте новый пароль. Штатный шаблон Reset password использует тот же разрешённый адрес `/auth/confirm`.

### Почта, OAuth и проверка из архива

Подтверждение адресов обязательно в облачном режиме. Для отправки за пределы команды настройте Custom SMTP в Authentication → Emails → SMTP Settings. Пароль приложения хранится в панели Supabase. В действующем учебном проекте подключён Gmail SMTP.

В шаблоне Confirm sign up можно использовать ссылку `{{ .RedirectTo }}?token_hash={{ .TokenHash }}`. Штатный шаблон восстановления пароля использует PKCE: откройте письмо в том же профиле браузера, где запрошен сброс. Для OAuth укажите в Google Cloud callback Supabase `https://<project-ref>.supabase.co/auth/v1/callback`, а локальный origin и пути возврата задайте в Supabase. Если приложение остаётся в Google Testing, добавьте проверяющего в список тестовых пользователей по согласованию.

Для чистого локального запуска достаточно `npm ci` и `npm run dev`. Для облачного прогона проверяющий создаёт свой проект Supabase, один раз применяет миграцию, добавляет значения в `.env.local` и перезапускает Vite. Уже применённую в учебном проекте миграцию повторно вручную не запускают. Проверьте `npm run build` перед упаковкой. Реальные значения конфигурации и учётные данные в архив не включаются. Актуальные результаты и ограничения проверок — в [чек-листе](CHECKLIST.md).
